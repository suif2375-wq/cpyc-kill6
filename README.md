## 🔥 核心卖点

1. **双引擎互为校验** — kill1 V8 条件决策树 + kill2 独立算术公式，两套逻辑独立运算，任一引擎误杀即不计数
2. **规律挖掘三件套** — 跨期切块组合挖掘（移植自 lottery-analyzer）：胆码（至少一位开出）/ 毒胆（全部不开）/ 和尾杀号 ×3，逐期滚动回测并如实对照随机基线
3. **每日自动更新** — 北京时间 21:16 / 21:26 / 21:30 / 22:00 四次 cron 自动抓数、回测、发布，无需人工干预
4. **无未来信息** — 回测严格按期号回溯，输入仅上期开奖号 `(b, s, g)`，不含任何未来数据，数字可审计
5. **纯函数零依赖** — Go 单二进制，无数据库无运行时依赖，本地/云端/Docker 任意部署
6. **透明可自建** — 数据源、引擎、回测逻辑全部开源，自带升级触发器（100 期 <70% 或单月下滑 ≥8pp 自动红条告警）

## 🔎 规律挖掘（跨期组合参考）

移植自开源库 [lottery-analyzer](https://github.com/liangguifeng/lottery-analyzer)（MIT）的跨期规律路径挖掘引擎：

- **切块**：历史按期号切成「3 期规律区间 + 1 期验证期」的块
- **组合**：跨期取位置组合（如 `1_1|2_2|3_1` = 第 1 期百位 + 第 2 期十位 + 第 3 期百位），共 C(9,3)=84 种
- **连续命中**：前 3 块（从最新往旧）全部命中的组合才算稳定规律
- **五类分析器**：胆码（至少一位开出）/ 毒胆（全部不开）/ 杀百个·百十·十个和尾

页面逐期滚动回测（近 100 期 + 全量），**如实对照随机基线**——胆码/毒胆约 5 成、和尾约 9 成，不做任何夸大。规律明细（路径 + 最大连续命中块数）可展开审计。

排列3/排列5模型说明：

- 每个位独立输出 2 个排除数字；
- 排列3复用上游 V9 双引擎的三位结构；
- 排列5使用万/千/百、十、个位的局部三位上下文特征；
- `lottery-analyzer` 的跨期胆码/毒胆引擎已泛化到任意位数，并作为推荐组合的软评分特征；主杀号仍以长期样本外更稳的 V9 结果为准；
- 每期只使用该期之前的历史数据，模型结果按滚动窗口回测；
- 页面同时展示近100期表现、全量表现和随机基线，避免只看单一窗口。
- 每个彩种额外生成10组推荐号码：先排除当前杀号，再按位置评分、和值、跨度、奇偶结构排序，并对相同位模式做轻微去重，避免10组完全重复。
- 双杀号始终去重：当两个公式输出同一数字时，使用确定性的备用候选替换第二个号码，确保每个位的 2 杀都是两个不同数字。
- 数据更新任务在北京时间 21:16、21:26、21:30、22:00 执行，覆盖开奖后数据源延迟场景。
- 推荐区支持“历史查询”：从本次部署开始持久化推荐记录，最多保存最近 100 条，可按期号搜索；每期推荐只使用该期之前的数据，旧的自动回算记录已清除。
- 推荐首位做均衡约束：在候选足够时，同一首位数字最多出现 2 组，降低“多数号码都以1开头”的集中风险。

## Lotterymcp 算法评估

已对 [Markovmodcn/Lotterymcp](https://github.com/Markovmodcn/Lotterymcp) 中公开的 `three_digit_analysis.py`（排列3）和 `positional_sequence_analysis.py`（排列5）按其原始评分公式做滚动样本外测试，工具位于 `tools/lotterymcp_probe`。

按该仓库“每期 top10 组合中是否包含完整开奖号码”的口径，最近1000期结果为：排列3 exact@10 约 1.4%，排列5 exact@10 为 0.0%。这没有形成可稳定复用的优势，因此没有替换当前 V9 主杀号；Lotterymcp 的跨期/位置统计仍作为研究工具保留。

网站访问密码：修改 `report/report.go` 中的 `DefaultSitePassword` 常量，重新生成 `index.html` 后生效。当前默认密码为 `123456`。这是静态页面前端校验，只适合作为访问门槛，不提供服务端级别的保密。

  -csv /data/fc3d-history.csv -html /data/index.html -kill6 /data/kill6_history.json
